[ Build notes for a finished queue ]

One true flag, one oversized bravo.

The Final Line is a Next.js static celebration for the exact moment dailyKpiCompleted becomes true. It does not turn the finish into another dashboard. It gives the fact room, rhythm, and a live typographic flourish the learner can conduct before leaving the queue behind.

The idea

Most completion screens are a badge, a burst, and an immediate route to more work. This one stays with the ending. The empty queue is treated as earned space, and every section repeats the same clear fact in a different register: proof, applause, reflection, and rest.

The centerpiece is an instrument, not a progress meter. Four real variable axes shape the words “You did it,” while size, tracking, italic, editable text, and celebration presets let each learner choose the volume of the moment. The page never asks what comes next. Its voice is warm, exact, and unembarrassed by a full stop.

The stack

  • Next.js 14 (App Router) with output: ‘export’. The build emits plain HTML for a quick, durable celebration. React is reserved for the seven instrument controls, presets, clipboard action, theme switch, and motion state.
  • The static-host recipe: basePath: ‘/glyphica’ + assetPrefix + trailingSlash: true in next.config.mjs, followed by an export that keeps every route portable.
  • Self-hosted variable fonts through next/font. Fraunces carries the expressive final line, Inter keeps the supporting copy calm, and Spline Sans Mono makes the completion record feel indisputable. The axes request keeps the flourish live:
const display = Fraunces({
  subsets: ['latin'],
  style: ['normal', 'italic'],
  axes: ['SOFT', 'WONK', 'opsz'],   // + wght, variable by default
  variable: '--font-display',
});
  • Zero images. The giant “Done,” its finish-line rules, the Bravo Scholar poster, the live completion card, and the final record are all HTML and CSS. Even the mark is an inline SVG built from the geometry of a last line and an overshoot dot.

Signature technique — the victory instrument

The interaction reduces to one CSS string. Axis state becomes font-variation-settings on the final line, so the browser’s font engine supplies the motion and the learner supplies the mood. This is the render path in components/AxisPlayground.tsx:

const settings =
  `"opsz" ${opsz}, "wght" ${wght}, "SOFT" ${soft}, "WONK" ${wonk ? 1 : 0}`;

<p
  className="spec-word"
  style={{
    fontVariationSettings: settings,
    fontSize: `min(${size}px, 16vw)`,
    letterSpacing: `${(tracking / 100).toFixed(3)}em`,
    fontStyle: italic ? 'italic' : 'normal',
  }}
>
  {text}
</p>

Two details keep the flourish from feeling like a settings panel. First, the letters settle through transition: font-variation-settings 0.45s var(--ease), so a new weight lands instead of snapping. Second, before the first interaction, the line quietly breathes through weight and optical size. The page begins applauding on its own, then hands over the baton the instant a learner touches a control:

useEffect(() => {
  if (reduced || interacted || !stageInView) return;
  let raf = 0, last = 0;
  const t0 = performance.now();
  const loop = (t: number) => {
    if (interactedRef.current) return;
    if (t - last >= 42) {
      const s = (t - t0) / 1000;
      setAxes((p) => ({
        ...p,
        wght: Math.round(560 + 320 * Math.sin(s * 0.55)),
        opsz: Math.round(80 + 64 * Math.sin(s * 0.31 + 1.4)),
      }));
      last = t;
    }
    raf = requestAnimationFrame(loop);
  };
  raf = requestAnimationFrame(loop);
  return () => cancelAnimationFrame(raf);
}, [reduced, interacted, stageInView]);

The loop is throttled to about 24fps, pauses when the stage leaves view, stops for good on first interaction, and never starts under prefers-reduced-motion. The controls still work without animation. Below the CSS readout, the same victory line echoes at four fixed sizes with optical sizing mapped to each one.

Details that protect the moment

  • The readout is real CSS. The learner can copy the exact declaration behind the flourish, turning a ceremonial interaction into a small, honest keepsake.
  • Real form controls. The axes are native input[type=range] and the two switches are checkboxes. Keyboard input, focus rings, and screen readers remain first-class guests at the celebration.
  • Light is the resting state. Warm paper gives the finished queue breathing room, while dark mode becomes the quiet room after the applause. An inline bootstrap reads the saved theme before first paint, avoiding a flash.
  • Content never depends on motion. Hero rises and scroll reveals exist only after JavaScript adds an enhancement class. Without it, every congratulation is already present and readable.
  • One final-stroke ease. cubic-bezier(.32, 0, .12, 1) gives reveals, controls, count-ups, and variable letters the same crisp arrival.
  • The background is ruled like a completion card. A fixed 28px rhythm and page-margin lines make the entire page feel like one carefully signed record.

The encore form is deliberately ceremonial. It validates and confirms in place, but sends and stores nothing. The learner gets a closing gesture without creating an account, a lead, or another obligation.

Ship the applause as static HTML

Four commands take the finished celebration from export to GitHub Pages:

npm run build                  # next build → out/ (static export)
rm -rf docs && cp -r out docs  # Pages serves the celebration from /docs
touch docs/.nojekyll           # preserve the generated _next assets
gh api --method POST /repos/bswxyz/glyphica/pages \
  -f 'source[branch]=main' -f 'source[path]=/docs'

With trailingSlash: true, this colophon exports as /guide/index.html, so it needs no server-side routing. Local development remains npm run dev at localhost:3000/glyphica.
